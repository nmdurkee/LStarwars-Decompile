PC character animation playback reconstruction

The isolated original executable now agrees byte-for-byte with an independent
finite Python reconstruction in 34,000 synthetic cases: 18,000 UpdateAnimTimer
(0x62e760) cases and 16,000 complete UpdateAnimPacket (0x62e9b0) cases. Every one
of the 72 packet bytes is checked, including untouched bytes. No original callee
or callback was replaced and no live game process was started.

Authored verification adds 2,911 AN3 end-frame comparisons through the original
0x5ca470 and 7,200 consecutive playback frames using native-loaded Qui-Gon
definitions and actual ANI headers. All 44,111 comparisons have zero mismatches.
The native anim_start handler 0x585760 and its original parser/name-lookup callees
processed all 58 authored Qui-Gon blocks in first-load mode 0x20. It produced 57
definitions; swipeBehind has no action directive and the native handler skips

0x40 and the full character configuration dispatcher are outside this fixture.

Packet layout (object embeds this packet at +8):
  +00 current time f32; +04 previous time f32
  +08 blend elapsed f32; +0c blend duration f32
  +10 source clip time f32; +14 target clip time f32
  +18..2f preserved unknowns
  +30 flags byte; +31 blending byte
  +32 source action i16; +34 target action i16
  +36 current action i16; +38 previous action i16; +3a requested action i16
  +3c source reversed; +3d target reversed; +3e current reversed
  +3f..41 preserved unknowns; +42 overlay action i16 (-1 absent)
  +44 preserved unknown f32

CORRECTION to earlier prose: +32 is SOURCE and +34 is TARGET. Accordingly,
object+3a is source and object+3c target. AnimPlaying 0x62f150 with arguments
(packet, action, 1, 0) accepts the current/target action, not the source action.
CharacterContexts.PlayingTimeOffset parameter labels and death-readiness text
have been corrected; offsets and positional call behavior were already correct.

Packet flags: 01 finished,02 looped,04 changed,08 reverse-time playback,
10 paused,20 zero frame step,40 blend finished,80 force restart. Flags are cleared
per update except values explicitly produced by that update. Old pause applies
only to the normal single-clip timer branch. Previous time captures current time
or the blend target time before the update. A zero frame step exits with flag20.

Blends use the minimum of source blend-out and destination blend-in when both
exceed this update's blend step. Looped clips with equal FPS and equal end frame
start the target at the source phase; others start at1 or the end for backwards
playback. A zero blend-in destination interrupts immediately. Blend mode1 can
interrupt using source or target according to which half of the blend elapsed.
The PC unconditionally overwrites the interrupted source reverse choice with
the current reverse flag; this oddity is preserved. Blend completion copies the
target ID/time/reverse state to current. Overlay animation has separate source
and target timers; loop/finished events come only from the target.

Timer definitions (native76-byte animdata records): flags+4 (bit2 cycle,
bit80 can play backwards), action i16+8, blend-in/out+10/+14, FPS+18,
movement reference+1c, maximum FPS+20. If reference>0, rate becomes
float32((movement/reference)*FPS), with native intermediate precision, then a
same-sign nonzero maximum clamps it. The ordinary caller passes absolute motion
into the timer. Frame delta is frameStep/30*rate, optionally reversed and scaled
by backwardsMultiplier. Loop range is1..endFrame with span(endFrame-1); endpoint
<=1 collapses to1. Noncycling clips clamp and emit finished when events enabled.
Requested backwards direction changes the reverse state at loop boundaries.
ANI4/ANI5 endFrame is u16(header+0a)+u16(header+0e); legacy is firstfloat32.

PC arithmetic is material: x87 precision control is64 significand bits. A
division rounded to64 bits followed by multiplication can change which side of
a float32 midpoint is reached. Three original cases differed by one float32 bit
with ordinary double/algebraic reassociation. The integer-based helper now
reproduces the intermediate rounding. It is a finite arithmetic subset, not a
general x87 emulator. The shared FiniteX87.Dot3PlusConstant facade additionally
supports the geometry worker's left-associative plane math with cancellation.

Orchestration boundary (0x418ca0, observed native source/assembly):
  object+40 = object+3e and object+7f0 = object+7ee before selection.
  Unless object API flags+1f8 bit40000 is set, invoke characterData+1c callback.
  Apply action override +3ee/+3f0 including sentinel233/context28 condition.
  Missing model and selected death/fade states return before playback.
  Select movement speed from pad+28/+34 or movement projected onto facing;
    special character configuration and context45 modify this selection/rate.
  Call 62e9b0(model, object+8, dt*30*rate, signedMovement, dt*rate,
    gameCharacterData.backwardsFactor).
  Changed action95 has additional random phase treatment.
  Then AutoWeaponOnOff58dd90 and AddFootSteps58bc60 execute.
This wrapper and its callback/effect dependencies are NOT implemented or claimed
as covered by UpdatePacket. Context selection and resolved clip construction are
host adapters. AnimationPacket.FromObject/CopyToObject bridge the existing
PcObjectImage context module; PlaybackClip.FromDefinition accepts recovered raw
definition/header bytes. Neither adapter guesses callback ordering or time.

The timer's PC calling convention is unusual: AX carries action ID and EDI the
model pointer, while remaining arguments are on the stack. Pseudocode alone
omits these inputs. The NativeX86 fixture explicitly seeds those registers.

Limits: finite ordinary metadata, valid clip references, bounded loop counts;
no NaNs, invalid pointers, extreme ranges or signed-zero corner-case equivalence
claim. Deterministic authored request schedules are test fixtures, not recovered
player/AI choices. Skeletal pose interpolation/export is separately verified in
the earlier animation reports; playback does not itself evaluate/render poses.
